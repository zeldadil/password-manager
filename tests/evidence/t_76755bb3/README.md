# Evidence — t_76755bb3: ApiClient called unbound `window.fetch` ("Illegal invocation")

Collected on 2026-10-11 on Linux (Node v22.23.3, pnpm 9.12.0, Vite 8.3.0, Playwright
Chromium). Base: `origin/master` at `0930d9f`. Dev DB created with
`pnpm --filter @password-manager/api migrate`. All credentials are synthetic
(`@example.test`). Tokens are never printed: the harness reduces the
`Authorization` header to its scheme plus a "has a credential" boolean.

## Root cause

`apps/web/src/api/client.ts` stored the global `fetch` as `this.fetchImpl` and called it
as `this.fetchImpl(...)`. In a browser the receiver is then the `ApiClient` instance, and
`window.fetch` rejects it with
`TypeError: Failed to execute 'fetch' on 'Window': Illegal invocation`.
`ApiClient` turned that rejection into a `network` `ApiError` before any request left the
page, so the Vault showed "Failed to load resources." and never sent
`GET /api/v1/resources`. The unit tests did not catch it because they inject `fetchImpl`
mocks, and Node/jsdom `fetch` does not check its receiver.

## Change

- `apps/web/src/api/client.ts`: the default is now
  `(input, init) => globalThis.fetch(input, init)`. It calls `fetch` with the global
  object as receiver, and it reads `globalThis.fetch` at call time.
- `apps/web/src/api/client.test.ts`: 3 new tests, "ApiClient — default fetch (no
  fetchImpl injected)". They use `vi.stubGlobal('fetch', ...)` with a stub that rejects
  with the browser's "Illegal invocation" `TypeError` when its `this` is neither
  `globalThis` nor `undefined`. The tests cover:
  1. a GET with the Bearer header, and a valid receiver;
  2. a stub installed after the client was constructed is still used;
  3. the 401 → `/auth/refresh` → retry path, where all 3 calls get a valid receiver.
